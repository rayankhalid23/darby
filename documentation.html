1. نظرة عامة على المشروع والمعمارية (System Architecture Diagram)

🎯 هدف النظام

منصة داربي (Darby) هي منظومة متكاملة لإدارة النقل المدرسي الذكي، تهدف لربط أولياء الأمور والسائقين وإدارة النظام (الآدمن) عبر شبكة تفاعلية تتيح إدارة طلبات الاشتراك، تتبع الرحلات المباشرة (GPS)، إثبات الصعود والهبوط بواسطة الـ QR Code، إدارة الغيابات والشكاوى، ومعالجة المدفوعات والفواتير.

🛠️ التقنيات والحزم الأساسية (Tech Stack)

  • Framework: Laravel 11.x / PHP 8.2+
  • Database: MySQL 8.0
  • Authentication: Laravel Sanctum (Token-Based Authorization & Signed URLs)
  • API Standardization: Eloquent API Resources + FormRequest Validation
  • Storage: Laravel Storage Disk (Public / Private Documents & Images)

3. مخطط تدفق البيانات والدورة الحياتية للطلب (API Sequence Diagram)

يوضح مخطط التتابع التالي الدورة الحياتية لمعالجة الطلب (Request/Response Lifecycle) من لحظة إرساله بواسطة المستخدم عبر Sanctum Authentication، مروراً بالتدقيق ومنطق العمل وحفظ المعاملة في قاعدة البيانات، وصولاً لتنسيق الرد النهائي:

sequenceDiagram
    autonumber
    actor Client as 📱 التطبيق (Mobile App / Web)
    participant Route as 🛣️ المسارات والحماية (Sanctum Auth)
    participant Controller as 🎮 الكنترولر (API Controller)
    participant Service as ⚙️ السيرفس (Business Service)
    participant DB as 🗄️ قاعدة البيانات (MySQL DB)
    participant Resource as 📦 التنسيق القياسي (API Resource)

    Client->>Route: POST /api/parent/requests (Bearer Token & Payload)
    Route->>Route: فحص وصلاحية Sanctum Auth Token & Role
    alt التوكن غير صالح أو منتهي
        Route-->>Client: 401 Unauthorized {status: false, message: "Unauthenticated"}
    else التوكن صحيح
        Route->>Controller: تسليم الطلب إلى الكنترولر المعني
        Controller->>Controller: فحص وتدقيق البيانات عبر FormRequest
        alt فشل التدقيق في البيانات
            Controller-->>Client: 422 Unprocessable Entity {errors: [...]}
        else نجاح التحقق في البيانات
            Controller->>Service: استدعاء دالة الخدمة (createSubscriptionRequest)
            Service->>DB: فتح معاملة مالية وقاعدة بيانات (DB Transaction)
            Service->>DB: إدراج البيانات في جدول `requests` و `request_children`
            Service->>DB: تثبيت وحفظ المعاملة (Commit Transaction)
            Service-->>Controller: إرجاع الموديل المعالج
            Controller->>Resource: تحويل الموديل بواسطة API Resource
            Resource-->>Client: 201 Created {success: true, data: {...}}
        end
    end

5. منطق العمل والخدمات الذكية (Business Logic & Core Services)

🔄 1. دورة حياة طلب الاشتراك والعقد (Subscription Lifecycle Flow)

تبدأ العملية باختيار ولي الأمر للسائق وتحديد الأبناء والمدرسة. عند إرسال الطلب، يتلقى السائق إشعاراً فورياً. في حال قبول الطلب، يقوم كائن ContractService آلياً بتوليد عقد موثق بصيغة PDF وتفعيله وإصدار فاتورة مدفوعة.

🛑 2. نظام حساب وتعديل الغيابات اللحظي (Real-time Absence Recalculation)

عندما يقوم ولي الأمر بتسجيل غياب لطفل لليوم الحالي عبر setAbsence:

  1. يتم حفظ السجل في absence_logs.
  2. تستدعى دالة الحماية الحية recalculateActiveTripsForChild($childId) داخل TripLifecycleService.
  3. إذا كانت هناك رحلة قائمة ومفعلة حالياً للسائق (Trip status = 'started')، يتم تحديث مسار الحافلة فورياً وإزالة المحطة الخاصة بالطفل لتوفير وقت السائق وتنظيمه.

6. دليل بيئة التشغيل والتنفيذ (Environment & Setup Guide)

⚙️ 1. أوامر التشغيل والـ Seeders

# 1. تنفيذ الهجرات
php artisan migrate

# 2. زرع بيانات الأطفال والاشتراكات الكاملة (بدون مسح البيانات السابقة)
php artisan db:seed --class=AddChildrenAndSubscriptionsSeeder

# 3. زرع رحلات نشطة للأطفال 1, 2, 3 طوال أيام الأسبوع
php artisan db:seed --class=Children123TripsSeeder

# 4. تشغيل السيرفر المحلي للشبكة المحلية (LAN Access)
php artisan serve --host=0.0.0.0 --port=8000
✅ جاهزية الملف للطباعة والعرض التفاعلي: هذا الملف مجهز بمكتبة Mermaid.js لتوليد الرسومات والمخططات تفاعلياً، ويمكن طباعته مباشرة عبر (Ctrl + P) كملف PDF عالي الدقة بدون أي تعارض في الصفحات.
